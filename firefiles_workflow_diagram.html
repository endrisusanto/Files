2 Workflow Inti — Satu Berkas dari PC sampai Samba

Urutan lengkap yang dipicu saat sebuah file selesai diunduh di folder staging. Langkah 1–5 sisi desktop, 6–10 rantai eksekusi.

1
Berkas baru muncul di staging E:\SUBRO
watch_source() pakai crate notify (event system) dengan debounce 200 ms. Kalau event OS terlewat, emit_loop() polling tiap 5 detik sebagai jaring pengaman.
filesystem watcheremit "files"
2
Klasifikasi status berkas
Ekstensi .part / .crdownload / .downloading / .tmp → downloading. Gagal dibuka read (file_is_available()) → locked. Hanya .md5 / .zip / .txt yang terbaca → ready dan boleh diantrekan.
downloadinglockedready
3
React terima event → auto-push
listen("files") update state; bila localStorage("auto_push") === "true" maka pushAllPending() jalan sendiri. Antrean di-sort: file prioritas dulu (priority_files), lalu nama A-Z.
auto_push ONpriority sort
4
Mutex anti-dobel & ringkasan antrean
isPushingRef.current menggagalkan push kedua saat masih berjalan. UI menghitung queue_total & queue_success (dari inSamba || isStaged) lalu mengirim keduanya ke Rust agar progres global akurat.
invoke("push_file")skip bila sedang push
5
Gerbang ganda sebelum push (proteksi HP)
Double-buffering: selama file staged di HP ≥ 3, loop tunggu 2 detik per iterasi. Storage guard: ruang bebas HP harus ≥ 1 GB (MIN_FREE_KB), kecuali force_transfer aktif. Ukuran file juga ditulis ke .meta supaya HP tahu total byte.
max 3 stagedmin 1 GB free.meta size handshake
6
adb push ke buffer HP + streaming progres
Perintah ADB dijalankan dengan CREATE_NO_WINDOW (Windows) dan stdout-nya dibaca baris per baris oleh pipe_progress(): regex mengambil persen, lalu app.emit("transfer", {file, percent, speed_bps}) ke UI. React merender progress bar + kurva NetworkChart.
emit "transfer"USB link
7
Bangunkan BridgeService dari jarak jauh
Setelah push selesai, Rust memanggil adb shell am start-foreground-service dengan extras: nama file, queue_total, queue_success. HP langsung mulai upload tanpa interaksi pengguna.
start-foreground-serviceservice hidup (WakeLock)
8
HP upload ke Samba via SMBJ
BridgeService membuka SMBClient → connect(host) → authenticate(guest) → DiskShare.openFile() lalu menyalin stream. Lalu lintas tetap di hotspot 5GHz lokal, jadi kecepatan maksimal meski internet mati.
smb://host/shareprogress byte per sample
9
Verifikasi status sejati (anti false-complete)
Berkas dianggap tuntas hanya bila nama muncul di sambaFiles (hasil watch_samba()) atau di phoneFiles (di-poll get_phone_files tiap 5 detik). Cache UI tidak dipakai sebagai satu-satunya bukti.
inSambaisStagedbukan cache lock
10
Cleanup staging + rayakan selesai
Sesuai post_transfer_action: file di PC dipindah ke folder BACKUP/ atau dihapus permanen. Taby di HP memicu animasi FILE TERKIRIM, dan TRANSFER SELESAI + confetti saat antrean kosong. Bila auto_push masih ON dan antrean belum habis, UI menjadwalkan pushAllPending() lagi setelah 1 detik.
backup | deleteconfettiloop sampai bersih
Ringkas satu baris: staging baru → klasifikasi ready → gerbang buffer/storage → adb push → service SMB → cek Samba/HP → cleanup + confetti

3 Mesin Rust — 6 Thread Latar Belakang Saat App Hidup

Semua di-spawn dari blok .setup() pada fn main(). Tiap thread punya interval sendiri dan mengirim event Tauri ke React.

Thread / loopIntervalTugasOutput

watch_samba() event Watcher pada mount Samba untuk mengenali berkas yang benar-benar sudah mendarat event samba-files
